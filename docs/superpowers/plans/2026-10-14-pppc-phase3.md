# PPPC Phase 3 Implementation Plan: Measuring Speedups

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Measure how close Phase 2's run time prediction is to reality: constant overrides for bench-sized runs, per-loop timing in generated C, seconds per cost unit, and a `pppc_bench` app whose committed output reproduces the paper's Table 4.1 and checks every loop verdict.

**Architecture:** Overrides are threaded from the options into the semantic pass (`check_program/4`). Timing is a codegen option (`generate_c/3` with `timed(Keys)`), fed the candidate loops from the analysis. `pppc_bench` (module `pppc_bench`, app `app/pppc_bench.pl`) builds three timed binaries per benchmark, runs them with `library(process)` at each thread count, and writes markdown; its summaries are pure predicates tested on canned data.

**Tech Stack:** SWI-Prolog 10.0.2 (devenv), plunit, `library(process)`, dicts, gcc 16 with OpenMP.

**Spec:** `docs/superpowers/specs/2026-10-14-pppc-phase3-design.md` (builds on the Phase 2 spec). Read its section 8 (revisions): linear and cg run about 0.2 s; bench threads are bound one per core.

**Provenance:** the code was prototyped, then staged from `master` (`0edb034`) one commit per task on branch `phase3-staged`, with `make test` passing at every commit, and replayed from `master` applying exactly the patches below. The RED and GREEN results in the `Expected:` lines are from that replay. A full `make bench` with the final harness took 198 s.

**How to apply a patch:** each code step gives a unified diff. Save the block (without the fence lines) to a file in your scratchpad and run `git apply FILE` from the project root. It must apply without fuzz; if it does not, the tree is not where the plan expects: stop and compare with the previous task's commit.

## Deviations from the spec

Decided while prototyping; each costs a rename if wrong.

- The C timing names are `pppc_time_s`, `pppc_time_n`, `pppc_time_where`, `pppc_wtime` and `pppc_time_report` rather than the spec's illustrative `PPPC_t`, `PPPC_n`: the runtime's names are lower-case `pppc_`, and `PPPC_` is the calibrator's prefix.
- `write_results/3` takes `+Notes` (the text kept after the marker) instead of `+Options`: the notes are the only thing the writer needs that is not in Results.
- Overriding the same constant twice is an error (`duplicate_const`); the spec did not say (Review Focus 1).

## Global Constraints

- Run every command from the project root inside the devenv shell: `devenv shell -- <command>`.
- SWI-Prolog 10.0.2 from devenv; never the system `/usr/bin/swipl`.
- Every new source or option error is a `pppc(_)` term with a message in `messages.pl`; exit status 1 for source and option errors, 2 for internal errors (spec 3.1, 5.4).
- Without `timing(true)` the generated C is byte-identical to Phase 2's (spec 4).
- Timing output goes to stderr only; a timed build's stdout equals the untimed build's (spec 4).
- Tests never depend on live timings: the bench smoke and app tests check only the shape of the output (spec 7.1).
- `make bench` is never part of `make test` or `make check` (spec 2).
- No yall lambda may mention a variable of its enclosing clause (Phase 1 ruling); use a named helper.
- Calibrate and bench only on an idle machine: check `uptime` first (load average well below 1).

## Review Focus

Inputs the spec implies that most plausibly break, each pinned by a test in the task that owns the code:

1. The same constant overridden twice (`--const n=1 --const n=2`) must be an error, not a silent choice — `override_twice` (Task 1), message `duplicate_const` (Task 1).
2. An override that makes a declaration invalid (`n=0` for `array[1..n]`) must give the ordinary semantic error at the declaration's line, not a crash — `override_empties_array` (Task 1).
3. A candidate loop inside a *function* (C has `pppc_result` and a `return` after the loop) must be timed and counted correctly — `timed_function_loop` (Task 3).
4. A thread list where the largest P is 4, or that lacks 4, must give one loop table, not a duplicate or none — `markdown` (threads 1, 2, 4: one table at P=4) and `bench_smoke` (threads 1, 2: one table at P=2) (Task 4).
5. A results file edited by hand, without a notes marker or missing altogether, must not lose the new results or crash — `no_notes` (Task 4), `app_keeps_notes` (Task 5).

Known limitation (documented in `generate_c/3`, not tested): loops are identified by routine and line, so if a serial outer loop and a candidate inner loop start on the same line, the outer one is timed. No benchmark is written that way.

+/** <module> Measure speedups and loop verdicts
+
+Reproduces the paper's Table 4.1 (section 4.3.6): for each benchmark,
+at the problem size given in a sizes file, the predicted and actual
+whole-program speedups at several thread counts, and for each
+candidate loop the predicted and actual time per execution, serial and
+parallel, with the verdict each implies.
+
+Three binaries are built per benchmark, all timed (pppc option
+timing(true)): `serial`, `parallel` (run time prediction at the largest
+thread count, Pmax) and `all` (every candidate loop parallel). `serial`
+runs K times, the others K times at each thread count P, under
+OMP_NUM_THREADS=P, OMP_PLACES=cores and OMP_PROC_BIND=close: one thread
+per physical core while there are cores left (with the default places,
+one per hardware thread, `close` would put threads 0 and 1 on the two
+hardware threads of one core). Medians are reported.
+
+Options of bench/2:
+
+  - threads(Ps)  thread counts (default: the speedup points up to the
+    number of CPUs);

+  - programs(Names)  benchmarks to run (default: all seven);
+  - sizes(File)  the sizes file (default `bench/sizes.pl`);
+  - dir(Dir)  where the programs are (default `test/programs`);
+  - cost(File)  the cost table (default: the shipped table).

+%   Run the benchmarks. Results is a dict bench{...} with the keys
+%   date, cpu, gcc, cost, repeat, threads, and programs: one dict
+%   prog{name, sizes, unit, speedups, loops, runs} per benchmark, where
+%   speedups is the predicted P-Speedup at Pmax, loops is P-LoopTimes
+%   (the loop_time/4 terms of pppc_predict/3 at P) for P = 4 and Pmax,
+%   unit is the cost table's seconds per unit, and runs is a list of
+%   run(Mode, P, WallSeconds, Timings) with Timings as parse_timings/2
+%   gives them.

+bench_program(Options, Sizes, Unit, Name, Prog) :-
+    (   memberchk(Name-Overrides, Sizes)
+    ->  true

+    option(repeat(K), Options),

+%!  speedup_rows(+Results, -Rows) is det.
+%
+%   One row(Name, SerialSeconds, Predicted, Actual) per benchmark, where
+%   Predicted and Actual are lists P-Speedup over the thread counts
+%   (Speedup is `none` if there is no value) and SerialSeconds is the
+%   median serial wall time.
+speedup_rows(Results, Rows) :-
+    maplist(speedup_row(Results.threads), Results.programs, Rows).
+
+speedup_row(Ps, Prog, row(Prog.name, Serial, Pred, Actual)) :-
+    median_wall(Prog.runs, serial, 1, Serial),
+    maplist(predicted_speedup(Prog.speedups), Ps, Pred),
+    maplist(actual_speedup(Prog.runs, Serial), Ps, Actual).

+predicted_speedup(Speedups, P, P-S) :-
+    (   memberchk(P-S0, Speedups)
+    ->  S is float(S0)
+    ;   S = none
+    ).
+
+actual_speedup(Runs, Serial, P, P-S) :-
+    (   median_wall(Runs, parallel, P, T), T > 0
+    ->  S is Serial / T
+    ;   S = none
+    ).
+
+median_wall(Runs, Mode, P, T) :-
+    findall(W, member(run(Mode, P, W, _), Runs), Ws),
+    median(Ws, T).
+
+%!  loop_rows(+Results, +P, -Rows) is det.
+%
+%   One loop(Name, Routine, Line, PredSerial, PredPar, Serial, Par) per
+%   candidate loop of each benchmark at P threads: predicted and
+%   measured time of one execution in seconds. A measured time is
+%   `none` if the loop never ran.
+loop_rows(Results, P, Rows) :-
+    findall(Row, ( member(Prog, Results.programs),
+                   loop_row(Prog, P, Row) ),
+            Rows).
+
+loop_row(Prog, P, loop(Prog.name, R, L, PS, PP, S, Par)) :-
+    memberchk(P-Times, Prog.loops),
+    member(loop_time(R, L, PS0, PP0), Times),

+    PP is PP0 * Prog.unit,
+    per_execution(Prog.runs, serial, 1, R-L, S),
+    per_execution(Prog.runs, all, P, R-L, Par).
+
+%   per_execution(+Runs, +Mode, +P, +Key, -Secs): the median over the
+%   runs of the loop's mean time per execution.
+per_execution(Runs, Mode, P, R-L, Secs) :-
+    findall(T, ( member(run(Mode, P, _, Ts), Runs),
+                 memberchk(R-L-N-Total, Ts),
+                 N > 0,
+                 T is Total / N ),
+            Xs),
+    (   median(Xs, Secs)
+    ->  true
+    ;   Secs = none
+    ).
+
+median(Xs0, M) :-
+    msort(Xs0, Xs),
+    length(Xs, N),
+    N > 0,
+    Mid is N // 2,
+    (   N mod 2 =:= 1
+    ->  nth0(Mid, Xs, M)
+    ;   Lo is Mid - 1, nth0(Lo, Xs, A), nth0(Mid, Xs, B),
+        M is (A + B) / 2
+    ).

+:- use_module(library(main)).
+:- use_module(library(option)).
+:- use_module(library(pppc/bench)).
+:- use_module(library(pppc/messages), []).
+
+/** <module> pppc_bench command line
+
+    swipl pppc_bench [-o FILE] [--threads 1,2,4] [--repeat K]
+                     [--program NAME]... [--sizes FILE] [--cost FILE]
+
+Runs the benchmarks (see pppc_bench) and writes the results as
+markdown to FILE or standard output. Text after the notes marker of an
+existing FILE is kept.
+
+Exit status: 0 success, 1 the bench failed, 2 internal error.
+*/
+
+:- initialization(main, main).
+
+opt_type(o,       output,  file(write)).
+opt_type(threads, threads, atom).
+opt_type(repeat,  repeat,  between(1, 1000)).
+opt_type(program, program, atom).
+opt_type(sizes,   sizes,   file).
+opt_type(cost,    cost,    file).
+
+opt_help(output,  "Write the results to this file (default: standard output)").
+opt_help(threads, "Comma-separated thread counts (default: 1-8 and the number of CPUs)").
+opt_help(repeat,  "Runs of each binary at each thread count; the median is kept (default 3)").
+opt_help(program, "Run only this benchmark (repeatable; default: all seven)").
+opt_help(sizes,   "Problem sizes file (default bench/sizes.pl)").
+opt_help(cost,    "Cost table file (default: the shipped table)").
+opt_help(help(usage), " [options]").
+
+main(Argv) :-
+    argv_options(Argv, Positional, Options0),
+    (   Positional == []
+    ->  catch(( bench_options_cli(Options0, Options),
+                bench(Options, Results),
+                output(Options0, Results) ),
+              pppc(E), failed(E))
+    ;   argv_usage(debug),
+        halt(1)
+    ).
+
+%   bench_options_cli(+CLIOptions, -Options): the options of bench/2.
+bench_options_cli(Options0, Options) :-
+    findall(P, member(program(P), Options0), Programs),
+    (   Programs == []
+    ->  Os1 = []
+    ;   Os1 = [programs(Programs)]
+    ),
+    (   option(threads(Text), Options0)
+    ->  thread_list(Text, Ps),
+        Os2 = [threads(Ps)|Os1]
+    ;   Os2 = Os1
+    ),
+    include(passed_on, Options0, Os3),
+    append(Os2, Os3, Options).
+
+passed_on(repeat(_)).
+passed_on(sizes(_)).
+passed_on(cost(_)).
+
+thread_list(Text, Ps) :-
+    split_string(Text, ",", " ", Parts),
+    (   maplist(number_string, Ps, Parts),
+        Ps \== [],
+        forall(member(P, Ps), (integer(P), P > 0))
+    ->  true
+    ;   throw(pppc(bench(bad_threads(Text))))
+    ).
+
+output(Options, Results) :-
+    (   option(output(File), Options)
+    ->  notes(File, Notes),
+        with_output_to(string(Text), write_results(current_output, Results, Notes)),
+        setup_call_cleanup(open(File, write, S), write(S, Text), close(S))
+    ;   write_results(current_output, Results, "\n")
+    ).
+
+failed(internal(Pass, Reason)) :- !,
+    print_message(error, pppc(pppc_bench, internal(Pass, Reason))),
+    halt(2).
+failed(semantic_errors(Errors)) :- !,
+    forall(member(pppc(E), Errors), print_message(error, pppc(pppc_bench, E))),
+    halt(1).
+failed(E) :-
+    print_message(error, pppc(pppc_bench, E)),
+    halt(1).
